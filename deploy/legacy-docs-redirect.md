# Retire the Engineering Documents hostname

The production document origins are `docs.onesa.eu` for every public document and `docs.internal.onesa.eu` for every internal document. The former `docs.engineering.onesa.eu` hostname has no document application, client registration, content store or publication workflow in this repository.

First qualify the internal TLS certificate, exact Identity callback, per-collection authorization and old bookmark resolution on the new internal host. For the existing Pages custom hostname, apply the supplied redirect-only Worker using the account-scoped Cloudflare deployment and `deploy/wrangler.legacy.jsonc`, or configure an equivalent edge redirect rule ahead of the old Pages application. Restrict the match to the exact old host and GET/HEAD requests for legacy documentation paths. Redirect to the **literal fixed origin** `https://docs.internal.onesa.eu` with the old path. Preserve only explicitly supported non-sensitive document-view query parameters. OIDC codes, magic-link proofs, access cookies, OAuth redirects, and signing transactions must not be replayed at the new hostname. Re-enter through the document's own sign-in for an expired transaction. The browser can preserve the fragment on an ordinary document URL.

Test anonymous requests to the old document and attachment paths, denial of unauthorized HR/search/download access, and the exact destination for an approved engineer. Verify public guides while signed out. Then detach the old Pages application from the legacy hostname and retire the corresponding old app/client when provider rollback evidence is in place. Keep the redirect rule for bookmarks. The rule is a compatibility route and serves no documents. Do not drop DNS or TLS for the old host while the bookmarks depend on it.
